# 麦当劳周末规划师

> 输入一座城市，输出一份「这个周末到底干嘛」的答案 —— 一份可以照着走的时间表，不是一个景点清单。

---

## 项目介绍

### 它解决什么问题

周末最难的从来不是「去哪」，是「几点去哪」。

攻略网站告诉你「XX 商圈很繁华」「必去打卡地 TOP10」，但你真正需要知道的是：这家店几点关门、那条街几点熄灯、两个人吃下来人均多少、现在领的券能不能在这家店用。

这个技能把这些问题变成一份单页 HTML 行动手册。它做三件事：

**1. 用门店当坐标，读出城市的作息**

同一个品牌在不同片区的营业时间，比任何「商圈分析」都诚实。广州天河 5 家店有 4 家通宵，从化 5 家只有 1 家；北京五道口一家通宵都没有，晚上 10 点整条街就散了。这些是硬数据，能直接推出「这个片区几点之后还有生活」。

**2. 把菜单拆到能复刻的程度**

一个巨无霸 11 层、513 千卡、钠 961 毫克，接口里可特调项只有五个。知道这些，你才知道控卡该去掉酱还是去掉芝士，也才知道自己在家做一个要花多少钱、会在哪一步翻车。

**3. 把券算成一张可以发群里的表**

券按「张」发，每张锁死一个 SKU 的低价。3 个人拼单 ¥75.5、人均 ¥25.2，比各点三件套省 ¥25。这个数不是估的，是按真实券价算出来的。

### 核心设计：数字全自动，判断留给人

这是整个技能唯一值得说的地方：

| 层 | 谁来做 | 内容 |
|---|---|---|
| 数据 | 麦当劳 MCP 接口 | 门店编码、地址、营业时间、菜单价、券、活动 |
| 判断 | 模型 | 哪几家值得去、时间怎么排、这条街几点熄灯、这个片区的麦麦和城区差在哪 |
| 渲染 | `build.py` + 模板 | 单文件 HTML，不联网、不依赖 CDN |

第一层不允许编。门店编码对不上就是错的，价格凭记忆写就是错的。
第二层不允许空。写「天河很繁华」没有价值，写「4/5 家通宵，说明夜间人流由地铁末班车撑着」才有。

### 输出长什么样

一份约 90 KB 的单文件 HTML，四屏内容：

```
首屏      数据条：N 家门店 / 96 种组合 / N 张券 / ¥14.9 起
01 城市漫游  门店列表 + 洞察卡 + 四时间点路线 + 片区作息对比 + 活动时间线
02 菜单拆解  巨无霸 11 层可视化 + 营养 + 12 项复刻清单 + 96 种随心配摇号器
03 券与价格  6 条营销原理（各带实测证据）+ 券池计算器 + 人均 20–30 元六方案
```

开头是两件事的必选：**你在哪个城市** → **这个周末想干嘛**。选完立刻长出一条具体时间表，不是「建议多出去走走」。

四个方向：

- **想出门** — 四个时间点走完一片城区
- **想逃离** — 出城，或者把最后两小时算清楚
- **想折腾** — 复刻一个巨无霸，12 项清单可打勾
- **想省钱** — 券池拼单，人均压到 25

## 安装方法

### 前提

| 依赖 | 说明 |
|---|---|
| WorkBuddy | 技能宿主 |
| 麦当劳 MCP 连接器（`mcd-mcp`） | 所有数据来源，**必需**。未连接时技能无法工作 |
| Python 3.8+ | 仅用标准库，**无第三方依赖**，不需要 pip install |

### 安装

技能是纯目录，复制即安装。放到用户级目录（跨项目可用）：

```bash
# macOS / Linux
cp -r mcd-weekend-planner ~/.workbuddy-ai/skills/

# Windows（PowerShell）
Copy-Item -Recurse mcd-weekend-planner "$env:USERPROFILE\.workbuddy-ai\skills\"
```

Windows 上如果 `python` 不在 PATH，构建时用托管解释器：

```
C:\Users\<用户名>\.workbuddy-ai\binaries\python\envs\default\Scripts\python.exe
```

### 验证

```bash
cd ~/.workbuddy-ai/skills/mcd-weekend-planner
python scripts/build.py \
  --data references/example-plan-guangzhou.json \
  --out /tmp/test.html
```

看到这个就装好了：

```
OK  /tmp/test.html
    2 个片区 / 10 家门店 / 3 张券 / 6 个方案
    广州 · 天河 · 广州 · 从化
    90 KB
```

打开 `/tmp/test.html`，页面应该完整渲染（这是用真实抓取数据生成的广州样例）。

### 卸载

```bash
rm -rf ~/.workbuddy-ai/skills/mcd-weekend-planner
```

## 使用示例

### 示例 1：只说城市

> **你**：成都这个周末不知道干嘛，帮我规划一下

技能会自己挑两个片区（一个市中心 + 一个郊区），拉数据，出页面。成都这次的实测结果：

- 春熙路 5 家店全在 **344 米**内，2 家真通宵（茂业百货、壹购广场）
- 温江 5 家店散在 **5.1–8.4 公里**，只有洲际亚洲湾一家通宵
- 巨无霸两边都是 ¥26，但麦辣鸡腿堡 ¥22.5 / ¥23、麦乐鸡 ¥14 / ¥14.5 —— 市区贵
- 反过来：麦香鱼 ¥23 / ¥22.5、双层鳕鱼堡 ¥25 / ¥24 —— 郊区便宜
- 温江独有：玫瑰红糖糍粑风味派 ¥5、泷盐星星麦旋风 ¥16、旋旋水手帽 ¥48.8

页面里「想逃离」那条线会告诉你：温江四家店 22:00 关门，唯一通宵的在 8.4 公里外，23:30 之前必须动身回城。

### 示例 2：指定片区

> **你**：我在广州天河，预算 30 块，周末想出门走走

跳过片区选择，直接锁定天河。输出「想出门」方向的时间表：

```
09:00  华南植物园            学生半价，园子大到能走三小时
12:30  天源路店 · 1400359    出园步行即到，随心配 14.9，坐窗边看车流
14:00  五山 · 华农酸奶 + 旧书店
18:30  燕岭路店 · 1400257    靠广州东站，看绿皮车进出站，收尾一杯浓浓黑巧
```

人均 ¥20–30，含一杯饮品。

### 示例 3：只要省钱

> **你**：周末约了 3 个人吃饭，怎么点最省

直接给券池表，可以一键复制发群里：

```
【周末券池 · 3 人】
券池拼单：全单 ¥75.5，人均 ¥25.2
 · 11.9 麦辣鸡腿堡券 ×3 = ¥35.7
 · 19.9 王牌炸鸡任选 2 ×2 = ¥39.8
 · 免费脆薯饼 ×3 = ¥0
对照：各点三件套 全单 ¥100.5，人均 ¥33.5
省 ¥25.0（25%）
```

页面里的计算器支持切 2 / 3 / 4 / 6 人，差价实时变。

### 示例 4：想动手

> **你**：想自己在家做一个巨无霸

给 12 项采购清单（可打勾、带进度条）、4 个必翻车点、成本核算：

- 肉饼每片 **45 g**，薄到透光 —— 做厚了煎完缩成肉丸
- 酸黄瓜碎必须挤干，否则酱稀成汤
- 生菜洗完必须甩干，不然面包 5 分钟就烂
- 芝士靠蒸汽融，别直接干烧

成本约 ¥20/个，门店 ¥25.5–26。省下的钱买不到时间 —— 建议当周末项目，不要当省钱手段。

## 目标用户

**主要：在校大学生**

这个技能是为「周末有空、预算有限、不想在宿舍躺两天」的人做的。默认人均 20–30 元，所有方案都压在这个区间里；学生麦金卡 ¥49/150 天那笔账单独算过（0.33 元/天，四舍五入等于白送）。

**其次：刚工作、周末没人约的人**

不想做攻略，也不想被「必去 TOP10」牵着走。给它一个城市名，二十分钟后有一份能照着走的东西。

**再次：城市观察 / 内容创作者**

如果你关心「一座城市的夜晚从几点开始变安静」，门店营业时间是比人口数据更直观的指标。技能输出的作息对比图（通宵店占比 + 最晚闭店时间）可以直接用。

**不适合**：

- 想找「拍照好看」的地方 —— 这个技能不评价景色，只排时间和钱
- 想要完整餐厅推荐 —— 只覆盖麦当劳，这是刻意的取舍（数据可得、门店够密、营业时间能反映片区作息）
- 想直接下单 —— 页面不联网，只能算不能买

```
│   └── template.html                     页面模板（样式 + 骨架 + 渲染逻辑）
└── references/
    ├── data-schema.md                    plan.json 字段表
    ├── mcp-recipes.md                    10 个 MCP 工具的调用配方与 6 个坑
    └── example-plan-guangzhou.json       广州两片区完整样例（可直接复制改）
```

### 数据流

```
用户给城市
   ↓
SKILL.md 规定调用顺序
   ↓
mcd-mcp：query-nearby-stores → query-meals → query-meal-detail
        → available-coupons → query-store-coupons
        → campaign-calendar → calculate-price
   ↓
模型写判断：insights / route / escape / priceNote / plans
   ↓
plan.json（schema 见 references/data-schema.md）
   ↓
python scripts/build.py --data plan.json --out weekend.html
   ↓
单文件 HTML（present_files 打开）
```

## 已知限制

**价格是快照。** 页面里每个数字都是抓取那一刻的到店自取价。门店有独立定价权限，同一商品不同店、不同时段都可能不一样，跨店比价才有意义。

**券的状态会变。** 早上一批券全是「可领取」，晚上再看前两张已经变成「已领取」。技能按接口返回的 status 填，但页面本身不联网，不会自动更新。

**可领 ≠ 可用。** 实测过：能领 3 张券，但 `query-store-coupons` 在目标门店返回空 —— 卡包里没有可用资产。页面里那句「进店前先在卡包确认可用门店」不是免责声明，是真实踩过的坑。

**只覆盖到店自取。** 麦乐送（`beType=2`）和得来速（`beType=5`）没做，因为外送的门店半径和营业时间逻辑完全不同。

**判断部分依赖模型。** 数据不会错，但「这家店值不值得去」是主观的。如果某条路线不合口味，改 `plan.json` 里的 `route.steps` 重新构建就行，不用碰模板。
